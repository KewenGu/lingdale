# 0027 玩家有一个自己的角色,在游戏里做的每件事都以它的名义

- 日期:2026-11-21
- 状态:生效。角色的长相、它在各个画面里怎么出现,出了方案等负责人挑
- 决定者:项目负责人

## 背景

家里有一个衣帽间([0026](0026-home-upgrades-and-four-activities.md)),它要有一个可以打扮的对象。而到这时为止:

- **画面里从来没有出现过人。** [美术规范](../design/07-art-direction.md)里没有人物的画法。
- **[愿景](../design/01-vision.md#不做什么)的"不做什么"里写着"没有自由走动的角色"。**

画家的方案时,绘制者把"小人画不画"列成了要负责人决定的问题,备选里有"不画"和"只在衣柜旁边放一个人台"。

## 决定

负责人定了:

- **小人就是玩家在游戏中的角色。玩家在游戏里的所有行为,都以这个角色的名义在做。**
- **角色要画。** 这次把它最基础的样子(默认的一身)和画法定下来,写进美术规范。
- **角色要能被打扮,**衣帽间换的就是它。这次不画各种衣服。
- **它在很小的尺寸下也要认得出;长相不能像任何已有游戏或动画里的人物。**
- **它能不能在场景里走动,没有定,不默认它能走。** "角色在矿洞、农场、牧场、地图这些画面里以什么方式出现"做成方案,由负责人挑。
- **这次不重画已有的矿洞、农场、牧场画面。**

## 理由

负责人给的是决定,没有展开理由。它解决的事是清楚的:衣帽间有了打扮的对象;玩家在游戏里有了一个"自己"。

## 被否决的方案

- **不画角色**(衣帽间只有衣柜),和**只放一个人台:** 绘制者列出的两个备选。负责人直接定了要画。
- **默认角色能在场景里走动:** 负责人没有说,所以不默认。走不走是方案之一,等负责人挑。

## 后果

- **愿景的"不做什么"改了一句。** 原来是"没有自由走动的角色、没有复杂的地图探索"。现在写成:有一个代表玩家的角色;
  它能不能走动没有定,定下来之前按不走动来做。负责人挑定出现的方式之后再改成最终的说法。
- **美术规范第一次要写人物的画法。** 三种长相、三种出现的方式画在[方案比较页](../design/home-screens/options.html)里,挑定之后写进规范。
- **现有的矿洞和农场没有给角色留位置,**两屏都排满了。角色如果要出现在这两屏里,要等它们下次改版时重新排。
- **"蓝色只表示水"和衣服有冲突:** 照现在的规则,角色不能穿蓝色的衣服。衣帽间设计之前要定。
- **肤色、发型能不能选,角色有没有名字和表情,都没有定。** 草样里的肤色和发色用的是色板里现成的颜色,没有新增。
- **"不像任何已有的人物"没法靠绘制者自己保证。** 草样是从这套画面自己的形状出发画的,没有参照任何具体角色;对外发布前要负责人过目。
- **代码没有动。** 核心层里没有"角色"的概念。角色不改变任何规则:答题的还是玩家,进度还是那一份。
