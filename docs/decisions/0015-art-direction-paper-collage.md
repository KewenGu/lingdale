# 0015 美术方向:彩纸拼贴

- 日期:2026-11-19
- 状态:生效
- 决定者:项目负责人

## 背景

每一篇对外内容都需要画面,农场界面也要按统一的风格来做,所以美术方向要在建工程之前定下来
([0012](0012-build-in-public.md))。美术由创作者主导审美、AI 协助产出([0013](0013-content-voice-art-and-budget.md))。

画风要同时满足七件事:

1. 扫一眼农场就看出哪些能浇水、哪些枯萎、哪些快收获(设计支柱 2)。
2. 手机竖屏,30 块地一屏放下,最多 120 块,缩小后仍可辨认。
3. 把"灵谷"这个名字带来的修仙联想拉回田园小镇([0011](0011-name.md))。
4. 治愈、有期待感,枯萎看得出来但不吓人。
5. 12 种作物在小尺寸下分得开。
6. 能做成好看的小红书封面、图文组和竖屏短视频。
7. 一个人加 AI 协助能长期产出。

为此做了四个方向的探索稿,画的是同一个农场场景,见[美术方向探索稿](../design/art-exploration/README.md)。
探索稿全部用代码绘制,没有使用图像生成模型。

## 决定

**选彩纸拼贴(探索稿里的方向 C):** 用彩色纸片剪出来、一层层贴起来的农场,纯色块、圆润的几何形状、没有描边。

具体规定写在[美术规范](../design/07-art-direction.md)里,以后以它为准。

## 理由

负责人看过四份探索稿的比较页后选了 C。比较页给出的推荐也是 C,理由是:

- **状态最好认。** 干土和湿土是两张明暗差很多的纸(实测对比度 2.64),水滴是一个饱和的蓝色图形。
  把农场缩到每块地约 28pt(相当于一屏看 120 块地)时,C 仍然清楚,水彩掉得最快。
- **状态靠变换,不靠重画。** 12 种作物、5 个形态、3 种健康状态,加上生长、枯萎、收获的动画。
  在 C 里它们都是同一组纸片换颜色、转角度、挪位置。画像素稿时验证了相反的情况:像素画的枯萎用程序变形明显更差,要逐张手画。
- **AI 协助的方式更稳。** 素材由代码或矢量工具直接产出,不经过"生成一张图再去修",没有逐张风格漂移。
  探索稿本身就是这样做出来的。
- **正文是单词。** 答题界面上的单词、音标、释义必须好读。C 用普通字体;像素方向的像素字体连音标符号都不全。

## 被否决的方案

| 方向 | 好在哪 | 为什么没选 |
|---|---|---|
| A 像素菜园 | 一眼是游戏,状态清楚,素材小 | "像素加种田"里已经有一个人人都知道的作品,很难不被拿来比较;中文像素字体对答题界面不友好;枯萎要逐张手画 |
| B 水彩绘本 | 治愈感和田园感最强,离修仙最远,最适合小红书 | 状态的可辨认度最弱,缩小后笔触糊成一片;难在成套一致;位图体积大,动画贵 |
| D 低多边形沙盘 | 有体积和光影,短视频最出彩 | 高的作物挡住后一行;建模和 3D 管线对一个人来说负担最重 |
| C 和 B 的折中 | C 的形状和状态画法,加上 B 的纸纹和柔和配色 | 没有否决,只是现在不做。如果 C 在真机上显得太冷、太像应用,这是第一个要试的调整 |

## 后果

- **选 C 要付的代价:** 它是四个方向里最容易被看成"一个应用"而不是"游戏"的。治愈感不是自带的,
  要靠配色、圆胖的形状和纸的质感经营。这个风险要在农场切片上真机之后、以及目标用户的反应里检验。
- **探索稿对 C 有利。** 代码最擅长画纯色的几何形状。水彩和 3D 用真正的工具做会比探索稿好看得多。
  所以这次比较在"认不认得出"上相对公平,在"好不好看"上偏向 C。这个决定的依据主要是前者和产能。
- **还没有问过任何目标用户。** 路线图原先的顺序是先把候选方案发出去征求意见,再由创作者定稿;
  实际是负责人先选定了。"这几种画风,你更喜欢哪个"这条内容仍然要发,素材已经备好,
  但[内容策略](../marketing/01-content-strategy.md#让观众参与决定)要求只问真问题,所以问法要如实:
  创作者已经选了 C,想听的是大家喜欢哪个、喜欢它的什么,意见用来调整 C 的细节(冷暖、手作感、要不要向 B 借一点纸纹)。
  如果目标用户的反应明显偏向另一个方向,要不要重新评估,由负责人到时决定。
- **选定之后,C 的画稿改了三处:** 主按钮的底从水蓝换成深一档的按钮蓝,等级和种子数的绿底换成深叶色
  (这两处白字的对比度原先只有 2.9),房子的窗户从蓝色换成墨绿(蓝色只留给"水")。比较页里现在看到的是改过之后的 C。
- **只画过农场这一屏。** 答题界面、单词卡片、收获动画、未解锁的地块、四季、小镇都还没有,见美术规范的"还没定的"。
- **有几条依据没有核实:** AI 图像工具画不好像素画、AI 对 3D 建模帮助有限,是对这类工具的了解,没有实测;
  微信小游戏主包 4MB 的上限来自第三方资料,没有核对官方文档。它们只影响 A、B、D 的评估,不影响 C 的规范。
- **AI 协助产出的美术能否用于正式上架仍然没有答案**,版权归属和各平台的披露要求见[路线图](../design/06-roadmap.md#未决问题)。
  用代码画并不自动解决这个问题。
- **画的过程中核实了一条和规则有关的事实:** "开花"不等于"快收获"。模拟显示田里下一次浇对就收获的作物占 20% 到 38%,
  开花形态只占 7% 到 18%(模拟数据,默认参数)。美术上用独立的收获标记补上了,规则没有改。
