# 0002 用 Cocos Creator,核心逻辑写成不依赖引擎的纯 TypeScript

- 日期:2026-11-15
- 状态:生效
- 决定者:项目负责人

## 背景

- 一个人开发。
- 只需要在手机上运行。
- 既要做成独立应用,之后也要能上微信和抖音小游戏。

## 决定

- 引擎用 Cocos Creator,语言用 TypeScript。
- 全部游戏规则写在 `core/` 里,不引用引擎、Node 或 DOM 的任何接口。
- 时间和随机数由调用方传入。
- 平台差异(存储、登录、支付、通知、分享)放在一层适配接口后面。

## 理由

- Cocos Creator 能用一套代码同时出原生应用、微信小游戏、抖音小游戏和网页版,这几个平台都有官方支持。
- 规则与引擎分离后,可以不开引擎就写测试、跑模拟。数值问题在画任何界面之前就能发现。
- 小游戏的运行环境不是浏览器,核心层只用 ES2015 标准库可以避免兼容问题。
- 这个游戏的循环跨越很多天。时间由参数传入,才能测试,也才能做"快进一天"的调试功能。

## 被否决的方案

- **Godot、Flutter。** 没有成熟的微信、抖音小游戏支持。
- **uni-app、Taro。** 能出应用和小程序,做文字界面省事,但动画和游戏手感弱,而产品的差异正在游戏感。
- **Unity。** 可以转小游戏,但包体大、流程绕,对这个体量不划算。

## 后果

- `tsconfig.core.json` 强制检查核心层的纯净,见[架构](../dev/architecture.md)。
- 界面层不能实现任何规则,只能调用核心层。
- 词库和音频不能打进安装包,需要按需下载。
- Cocos 工程还没有建,实际接入时可能发现需要调整目录结构。
