## 文档怎么维护

- **规则以[玩法规则](design/02-gameplay.md)为准。** 改规则先改它,再改代码。
- **画面以[美术规范](design/07-art-direction.md)为准。** 改风格先改它,再改画面。
- **数字要有出处。** 模拟得出的写明场景和参数,估的写明是估的。
- **状态变化时更新[路线图](design/06-roadmap.md)。** 未决问题有了答案就移到决策记录。
- **不写会很快过时的内容。** 代码里一眼能看到的东西不必在文档里重复,文档写的是为什么和怎么用。
- **已经不成立的内容要删掉或改掉。** 过时的文档比没有文档更糟。
