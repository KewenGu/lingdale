# 内容

内容指玩家要学的东西:卡片和卡组。游戏规则不认识"英语"或"单词",只认识卡片。

## 卡片与卡组

一张**卡片**是一个要记住的知识点,有正面和背面(`Card`):

| 字段 | 必填 | 说明 | 例子 |
|---|---|---|---|
| `id` | 是 | 卡组内唯一 | `abandon` |
| `front` | 是 | 要学的内容 | `abandon` |
| `back` | 是 | 它的意思 | `v. 放弃;抛弃` |
| `phonetic` | 否 | 音标 | `/əˈbændən/` |
| `example` | 否 | 例句 | |
| `exampleTranslation` | 否 | 例句翻译 | |
| `audioKey` | 否 | 发音资源的键,不是网址 | |

一个**卡组**是一组有顺序的卡片(`Deck`):`id`、`name`、`version`、`cards`。

新词按卡片在卡组里的顺序依次出现,所以卡组的顺序就是学习顺序。按词频从高到低排是最自然的做法。

## 题目怎么从卡片生成

题目不需要单独编写,全部由卡片自动生成:

| 题型 | 题面 | 答案 | 干扰项 |
|---|---|---|---|
| 看词选义 | `front` | `back` | 同卡组其他卡片的 `back` |
| 看义选词 | `back` | `front` | 同卡组其他卡片的 `front` |
| 拼写 | `back` | `front` | 无 |

这意味着卡组的质量直接决定题目的质量:

- `back` 要简短明确。太长的释义在选择题里一眼就能和别的选项区分开。
- 同一卡组里不应有 `back` 完全相同的卡片。系统会避免把相同的释义放进同一题,但它们在"看义选词"里无法区分。
- 卡组至少要有 4 张 `back` 互不相同的卡片才能出选择题,否则会退回成拼写题。

## 现有内容

`data/sample-deck.json`:30 个四级难度的英语单词,手工编写,只有 `front`、`back`、`phonetic`。
它只用于开发和接界面时调试,不是正式词库。

## 计划中的内容

**第一个正式词库:大学英语四级词汇。**

计划从开源词典 ECDICT 转换,它带有四六级、考研、雅思等标签和词频信息。转换脚本还没有写。

动手之前需要确认:

- ECDICT 的开源许可是否允许在商业产品中使用。
- 它的中文释义通常很长,包含多个词性和义项,需要截取或改写成适合出题的短释义。这一步的质量很关键。
- 例句和发音从哪里来。

**之后的方向**(不在当前范围内):六级、考研、雅思等更多英语词库;其他语言;允许玩家导入自己的卡组。

## 内容的技术约束

- **词库不打进安装包。** 小游戏平台的包体限制只有几 MB,词库和音频必须按卡组从服务器按需下载。
- **发音资源用键引用。** `audioKey` 存的是资源的键,由平台层决定从哪里加载。
- **卡组升级要兼容旧存档。** 存档按卡片 `id` 记录进度。新版本卡组可以增加卡片、修改释义,但不能改变已有卡片的 `id`。
- **单词可能撞上保留名。** 像 `constructor` 这样的词会被用作对象的键,代码里读取词的状态必须走 `getState`。

## 内容原则

- **准确优先。** 释义、音标错了,玩家学到的就是错的。宁可少,不可错。
- **一张卡片一个重点。** 多义词只取最常用的一两个义项,其余的以后作为单独的卡片。
- **对学习者诚实。** 不因为某个词难出题就把它从词库里拿掉。
