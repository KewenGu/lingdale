# 牧场这一边的画面

牧场、养牛羊的小屋、鸡舍的示意稿和绘制代码:牧场一屏、草地、割草答题、牲畜的各种状态、够不够吃、几天没来、做饲料、买卖、产出、小镇地图上的牧场。

背景:牧场的规则已经做完([决策记录 0022](../../decisions/0022-pasture-and-livestock.md) 到 [0025](../../decisions/0025-chickens-feed-and-sheep.md)),
但这一边没有任何画面。2026-11-21 照[矿洞那一边](../mine-screens/README.md)的做法补上。

五个取舍由项目负责人选定,记在[决策记录 0026](../../decisions/0026-pasture-screens-art.md);之后负责人又定了牧场一屏上不写字、见底用感叹号,记在 [0027](../../decisions/0027-no-text-on-pasture-alert-mark.md);画法的规定写在[美术规范的"牧场"一章](../07-art-direction.md#牧场)里,
这个目录是它的参考实现和记录。

## 怎么看

用浏览器打开,需要联网加载字体(Google Fonts)。

| 页面 | 内容 |
|---|---|

| 牧场一屏上的字 | 不写"够吃几顿""饿了几天"。这些点草垛、饲料桶、小屋、鸡舍才看到;草垛和饲料桶见底时探出一个感叹号(负责人看过两稿之后定的) | 第一稿:牌子上写全捆数,草地上方另有一张写着矮中高各几株的牌子。第二稿:两块两小行的牌子,栅栏上一句话 |

| 饿着和病了怎么标 | 乙 姿态加一个探出来的标记(空碗、药瓶) | 甲 只靠姿态;丙 每只头上一张写字的纸条 |

| 底部的路牌 | 1 牧场有一块去农场的路牌,农场不变 | 2 农场上再加一块去牧场的路牌;3 牧场只有"小镇" |

五个取舍里负责人选的都是绘制者建议的那一种;"屏上不写字"和"见底加感叹号"是负责人自己提的。

**绘制时自己定的,还要负责人过目**(在 `options.html` 最后一节):

- 买牲畜和卖牲畜都在小屋(鸡舍)那张纸上,不在商店。动物药和救急的牧草、饲料在商店新增的"牧场用品"一页。
- 牲畜死了只在"几天没见"那张纸上交代一次,用一朵小白花;牧场上不留墓碑或别的记号。
- 产出不用玩家去收,出了东西的那几只头上贴一片玉米黄的圆片。
- 商店的"全部卖掉"不带牧草和饲料。
- 饲料画成木桶,不画成布袋(布袋已经是词袋)。
- 院子垫一块深一档的草地,让纸白的牲畜立得住。
- 割草和做饲料的答题画面沿用矿洞的骨架:选项是四垄草、四块木板。
- 感叹号画成纸白圆片上一个墨绿色的感叹号(不是红色);"见底"的线是不够吃两顿。
- 点草垛看到的那张卡片:有几捆、够吃几顿、吃到什么时候;见底时才有"去商店救急"。
- 美术规范的原则 5 补了一句,说明牧场是"不吓人、不催人"的有意例外。措辞是绘制时写的。

## 画的时候发现的规则和界面问题

都没有改规则,这里只是记下来,同时记在[路线图的未决问题](../06-roadmap.md#未决问题)里。

1. **牲畜几乎是同时病、同时死的。** 玩家不在的时候草垛只减不增,所有牲畜在同一顿断粮,连着饿满 7 天一起病,再过 15 天一起死,前后只差一顿。
   "几只病了、几只没撑住"这种半好半坏的情况只出现在一两顿的窗口里。晚一天打开,就从"全都能救"变成"一只不剩"。
   示意存档里是按规则一顿一顿算出来的:走之前草垛 96 捆、饲料 34 份,离开 9 天时 6 只刚病、4 只饿着;24 天时 6 只没撑住、4 只今天不治也来不及;25 天时一只不剩。
2. **结算的结果只有总数。** `settlePasture` 返回病了几只、死了几只、生了几只,不分牛羊鸡。纸上要写"1 头牛、1 头小牛、4 只鸡",
   界面得自己比对结算前后的牲畜。死掉的牲畜直接从存档里消失,所以死亡只能在结算的那一刻交代。
3. **"五星作物喂鸡不划算"按星级说不准。** 售价还要乘种子的倍率(`producePrice`):四星的南瓜卖 30,和鸡蛋一样;五星的葡萄卖 75;三星的葡萄卖 25。
   画面按售价排序、按售价提醒。[玩法规则](../02-gameplay.md#鸡饲料)的"四星及以下划算,五星打平"和
   [Cocos 接入](../../dev/cocos-integration.md#牧场)的"默认挑星级最低的"只对基础种子的作物成立。
4. **界面上有两种"天"。** 规则用游戏日(12 小时),顶部的日期也是游戏日;负责人定惩罚时说的是现实的天(饿 7 天生病,病 15 天死)。
   牧场已经定了按"顿"和现实的天说;顶部的日期,以及矿洞和农场画面里的"天",还没有对过。
5. **美术规范有两处是"缺席不受罚"的时候写的:** 原则 5"蔫了,不是坏了:不吓人、不让人愧疚",和"不做什么"里的"不催人:没有倒计时"。
   牧场必须说"还能等几天",负责人又定了见底时用感叹号。现在的做法:感叹号是墨绿色的、只用在草垛和饲料桶上;还能等几天用一句话写出来、放在点开之后,不放走动的倒计时。
   规范的原则 5 里补的那一句是绘制时写的,措辞等负责人过目。
6. **做饲料会让草地上少哪一株草,事先说不出。** 做饲料取的是最早到期的词,它是高草还是矮草不一定。
7. **存粮一空,所有牲畜同时挨饿,** 院子里每只头上都是空碗,草垛上还有一个感叹号。标记在"只有几只有事"时好用,这种时候是重复的。
   反过来,**只剩最后一天时没有记号**:"今天刚病"和"今天不治就来不及"在牧场一屏上是同一个样子,靠的是打开时那张只出现一次的"几天没见"。
8. **养多了一屏放不下。** 模拟里第 120 天有 19 头牛左右(模拟数字)。院子最多画 12 只牛羊、8 只鸡,有事的排在前面,其余省略成"还有几只"。
9. **草很多时"割一轮草"是多少题。** 离开 9 天回来有 280 株,就是 280 道题。
10. **"怀上"这个按钮可能没人按。** 模拟里的学习者从不让牛怀小牛:怀着的 14 天少卖 1120 金币,买一头小牛便宜得多(模拟数字,见[数值与平衡](../04-economy-balance.md#7-牧场和养牛的账))。
11. **纸白的牲畜在草地上明暗对比弱。** 纸白对草地 1.30,病了的(纸白暗)只有 1.02。院子垫了草地暗之后是 1.70 和 1.33,仍然主要靠投影、深色的花斑和脸、标记。

## 这些画面是怎么来的

- **全部用代码绘制。** JavaScript 运行时生成 SVG。没有使用图像生成模型,没有使用任何第三方图片。
- 代码由 Claude 编写,属于 AI 协助产出的内容。对外发布这些画面时,按[内容策略](../../marketing/01-content-strategy.md#红线)的要求声明。
- **它们是示意稿,不是成品。** 用途是检验构图、配色,以及各种状态在手机上认不认得出。
- **动效都没有做,**答题之后只有关键帧。
- **画面不读取游戏数据。** 数字是手写的示意,规则以[玩法规则](../02-gameplay.md#牧场)为准。
- 不模仿任何具体的已有游戏的画面、角色、图标和配色。

## 示意数据

[`pasture-scene.js`](pasture-scene.js)。牛要吃饱 56 个游戏日才长大,所以用不了农场参考图那个第 31 天的存档。主存档是第 1 年秋季第 20 天:

- 小屋里 2 头大牛(一头怀着)、1 头小牛、1 只大羊、1 只小羊,一顿吃 6 + 6 + 3 + 4 + 2 = 21 捆;草垛 63 捆,正好 3 顿。
- 鸡舍里 3 只大鸡(一只在抱窝)、2 只小鸡,一顿吃 2 + 2 + 2 + 1 + 1 = 8 份;饲料 8 份,只够 1 顿。
- 草地上 41 株草:矮 14、中 18、高 9,割完是 77 捆。

口粮、长大和怀小的天数、饿多久生病、病多久死、各种买卖价抄自玩法规则和 `core/economy.ts`,不从 `core/` 读取,规则改了要跟着改。
词和释义取自 30 词的示例卡组。

## 导出参考图

[`../art-direction/`](../art-direction/) 里的 `pasture.png`、`pasture-town.png`、`pasture-grass.png`、`pasture-mow.png`、`pasture-animals.png`、
`pasture-enough.png`、`pasture-away.png`、`pasture-feed.png`、`pasture-trade.png` 从 `export.html` 导出:每个带 `id` 的 `.sheet` 或 `.solo` 元素是一张图,`id` 就是文件名。

做法和矿洞那一边相同:用 Playwright,视口 1900 像素宽,像素比 1.5,等字体加载完后对每个元素单独截图,再量化成 256 色的 PNG。
改了绘制代码或示意数据之后要重新导出。

```js
const page = await browser.newPage({ viewport: { width: 1900, height: 1000 }, deviceScaleFactor: 1.5 });
await page.goto('file://…/docs/design/pasture-screens/export.html', { waitUntil: 'networkidle' });
await page.evaluate(() => document.fonts.ready);
for (const id of ['pasture', 'pasture-town', 'pasture-grass', 'pasture-mow', 'pasture-animals', 'pasture-enough', 'pasture-away', 'pasture-feed', 'pasture-trade'])
  await page.locator('#' + id).screenshot({ path: id + '.png' });
```

小镇地图加了牧场之后的样子是 `pasture-town.png`;`town.png` 是加牧场之前的那一张,仍然从 `../mine-screens/export.html` 导出。

三稿的对比图(第一稿、两小行的牌子、不写字)留在 [`../../marketing/assets/pasture-screens/`](../../marketing/assets/pasture-screens/),给[选题库](../../marketing/02-content-backlog.md)第 19 条用。

## 检查过的

- `index.html` 和 `options.html` 在 390 像素宽的视口下没有脚本报错,没有横向溢出。
- 画面里的数字和规则逐项对过:口粮、买卖价、长大和怀小的天数、生病和死亡的天数、一株草割几捆。几种"几天没来"的存档是按规则一顿一顿算的。
- 草的三种高矮缩到一半、去掉颜色之后仍然分得开。
- 牧场用到的颜色对的明暗对比按 WCAG 的公式算过,见上面第 11 条。
- `../mine-screens/` 的两个页面在改动之后没有脚本报错。

## 没检查的

- 没有上过真机,只在桌面浏览器里按手机宽度看过。
- 没有做色觉模拟,只算了明暗对比。
- 没有问过任何目标用户。
