## 已完成

- **核心逻辑层**(`core/`):时间与日历、矿洞(摸底、练习、复习、矿石、词袋、答错的额度)、农场(种新词、换一个、浇水)、牧场(割牧草复习;用作物做鸡饲料;养牛、羊、鸡:长大、产出、生小的、挨饿、生病、用药、死亡;买卖牲畜,卖牧草和产出)、商店与种子种类、播种、浇水、品质与健康、收获、掌握度循环、卖矿石和作物、地块、经验与等级、三种题型的出题与判分、存档读写、统计。
- **测试**:142 个单元测试,覆盖全部规则和存档自洽性。
- **学习者模拟**(`sim/`):可以调参的 60 天模拟,用于验证数值。学习者按公开的 FSRS 记忆模型记和忘,能核对游戏说的"掌握"靠不靠得住。
- **项目基础**:文档体系、决策记录、格式化、持续集成。
- **内容策略**:对外内容的目的、受众、主线、质量标准,以及一份选题库。尚未发布任何内容。
- **美术方向**:选定彩纸拼贴,写成[美术规范](07-art-direction.md)。画过农场、矿洞、矿洞关门、词袋、商店、小镇地图和牧场,
  [矿洞这一边的画面](mine-screens/README.md)是 2026-11-20 补上的。全部是代码画的示意稿,没有动效,没有成品美术。
  [牧场这一边的画面](pasture-screens/README.md)是 2026-11-21 补上的:牧场一屏、割草、牲畜的状态、够不够吃、几天没来、做饲料、买卖、小镇地图上的牧场,
  画法写进了美术规范的[牧场](07-art-direction.md#牧场)一章(决策记录 [0026](../decisions/0026-pasture-screens-art.md)、[0027](../decisions/0027-no-text-on-pasture-alert-mark.md))。

## 当前阶段:原型

目标是尽快做出负责人自己能玩的版本,用 30 天自测检验"学习为里,游戏为表"是否成立。
通过标准见[愿景](01-vision.md#怎样算成功)。

原型只做核心循环(矿洞、商店、农场;牧场的规则已经有了,原型里做不做它的界面还没定,见[未决问题](#未决问题)),下面这些**不做**:料理、战斗、居民、剧情、矿石的加工和送礼、云同步、多卡组切换、变现。

我们边做边对外发布内容(见[内容策略](../marketing/01-content-strategy.md)),所以顺序上优先做看得见的部分,
并且每一步都要留下素材。

## 原型之后

顺序未定,取决于自测的结果。

- **小镇。** 现在只有一张地图和三个地方(矿洞、农场、商店)。负责人给的方向([决策记录 0018](../decisions/0018-town-map-as-hub.md)):
  玩家有一个家,花钱买装饰、升级家装;以后陆续开放更多地点,比如湖边钓鱼(做不同的题)、放映厅(看影视学语言);
  按词汇量或等级开放。这些都还没有设计。居民、金币的消耗出口也在这里。
- **矿石的用途。** 升级家园、加工、送人。现在矿石只能卖钱。
- **田里的杂物。** 杂草、石头、树枝可以捡来卖钱,作为开局的第一笔收入。负责人提出后决定先不做,保持开局简单。
- **料理。** 牛奶现在只能卖钱,以后可以做料理。负责人定的方向,还没有设计。
- **羊毛的用途。** 羊和牛现在只是产出的名字不同。
- **镐子。** 用矿石升级,提高出高级矿石的机会,给矿石一个卖钱之外的用途。讨论过,负责人决定先不做([决策记录 0024](../decisions/0024-ore-odds-and-taller-grass.md))。
- **牛的好感度和牛奶的星级。** 好感度靠喂养、抚摸、刷毛慢慢涨,决定牛奶的品质。负责人提出后决定先不做。
- **更多和单词挂钩的玩法。** 每一种都要是一条完整的学习路(见[愿景](01-vision.md#6-每种玩法都是一条完整的学习路))。料理、钓鱼、收集、交友、战斗,讨论过,都还没有设计。
- **数值调整。** 用真实的作答日志校正休息间隔、浇水次数、矿石和高级作物的价格。
- **听力题型和发音。**
- **云存档与账号。** 上小游戏平台后,玩家会在应用和小游戏之间切换。
- **微信、抖音小游戏适配。** 包体、存储、登录、分享。
- **社交。** 好友农场互访等。
- **分享卡片。** 收获、农场全景、每周总结等可以一键生成图片分享。
- **更多词库和语言。**
- **变现。**

## 未决问题

需要负责人决定,或需要数据才能回答的问题。解决后移到[决策记录](../decisions/README.md)。

| 问题 | 说明 |
|---|---|
| 缺席惩罚会不会把人吓走 | 牛连着一周没吃上草会生病,病了半个月不治会死(负责人的决定,[决策记录 0023](../decisions/0023-cows-grow-starve-and-die.md))。模拟里连着 10 天不来牛全病、买药能救,25 天不来牛死光。回来看到牛死了的玩家是重新养还是就此不玩,没有数据。真人试玩时要专门看。 |
| 小牛两个季节才长大,原型里看不到牛奶 | 两个季节是现实 28 天,原型的自测只有 30 天。按现在的占位数,养牛的头两个月是亏的。负责人说数值后面再调。 |
| 其余的牲畜数值 | 买价(牛羊第一只 200、每多一只贵 100;鸡 100、每多一只贵 50)、卖价、动物药 50、一株草割 1 到 3 捆,是开发时填的占位数。口粮、产出的价格和节奏、长大和怀小的天数、牧草和饲料的买卖价是负责人定的。 |
| 种田放牧的开局偏紧 | 牧草直接卖只有 2 金币一捆(负责人定的),小牛要一个月才出奶,这一个月种田放牧的人主要靠卖作物。模拟里四个种子有两个在开局用了兜底种子,60 天教会的词是 403(牧草卖 10 的时候是 419)。要不要让小牛长得快一些、或者开局给一点别的收入,等真人试玩再看。见[数值与平衡](04-economy-balance.md#7-牧场和养牛的账)。 |
| 养鸡不赚不亏 | 一份作物做 2 份饲料之后鸡养得起来了(模拟里默认的学习者两三只,学得吃力的四只)。养了牛的人再养鸡,每天的收入几乎一样:一个蛋是一份作物加一次复习换来的,那次复习本来可以去割草喂牛。 |
| 羊和牛怎么选 | 羊吃得少(一天 4 捆,牛 6 捆),羊毛三个游戏日一份、卖 100。同样 12 捆草,喂牛换 80 金币的奶,喂羊换 100 金币的毛,羊更划算一些。在羊毛有别的用途之前,这是两者唯一的区别。 |
| 牧场画面里绘制时自己定的几件事 | 五个取舍和"牧场一屏上不写字、见底用感叹号"负责人已经定了(决策记录 [0026](../decisions/0026-pasture-screens-art.md)、[0027](../decisions/0027-no-text-on-pasture-alert-mark.md))。还要负责人过目的:感叹号的样子(墨绿色,不是红色)和"不够吃两顿"这条线、买卖牲畜放在小屋那张纸上、死亡只交代一次并用一朵小白花、"全部卖掉"不带牧草和饲料、美术规范原则 5 里补的那一句的措辞;以及点开之后那几张纸上的字多不多。 |
| 牲畜只剩最后一天时,牧场一屏上没有记号 | 字拿掉之后,"今天刚病"和"今天不治就来不及"在牧场一屏上是同一个样子(卧着,头上一个药瓶),还能等几天要点小屋或者那只牲畜才看到。现在靠打开牧场时那张只出现一次的"几天没见"。[Cocos 接入](../dev/cocos-integration.md#牧场)写的是"牛快死的时候要提前说"。要不要给最后一天也加一个记号,由负责人定。 |
| 牲畜几乎是同时病、同时死的 | 画"几天没来"时按规则一顿一顿算出来的:玩家不在时草垛只减不增,所有牲畜同一顿断粮,连着饿满 7 天一起病,再过 15 天一起死,前后只差一顿。晚一天打开,就从"全都能救"变成"一只不剩"。要不要让它们错开(比如病了的按不同的快慢恶化),由负责人定。 |
| 界面上的"天"指哪一种 | 规则里的"天"是游戏日(12 小时),顶部的日期也是;负责人定惩罚时说的是现实的天。"够吃 3 天"照游戏日写,其实是一天半。牧场已经定了口粮按"顿"说、多久按现实的天说([决策记录 0026](../decisions/0026-pasture-screens-art.md))。顶部的日期,以及矿洞和农场画面里的"天",还没有对过。 |
| 喂鸡划不划算要看售价,不是星级 | 规则写"四星及以下的作物做成蛋划算,五星的打平",只对基础种子的作物成立:售价还要乘种子的倍率,四星的南瓜卖 30(和鸡蛋一样),五星的葡萄卖 75。界面"默认挑星级最低的""挑了五星时提醒"应该按售价来。牧场的画面是按售价画的;[玩法规则](02-gameplay.md#鸡饲料)和 [Cocos 接入](../dev/cocos-integration.md#牧场)的说法没有改。 |
| 牧场和规范的"不吓人、不催人" | [美术规范](07-art-direction.md)的原则 5 和"不做什么"是"缺席不受罚"时写的。现在有两处负责人定的例外:存粮见底时一个墨绿色的感叹号;还能等几天用一句话写出来,放在点开之后。原则 5 里补的那一句是绘制时写的,措辞等负责人过目。 |
| 结算的结果不分牛羊鸡 | `settlePasture` 只返回病了、死了、生了的总数。界面要写"1 头牛、4 只鸡"得自己比对结算前后的牲畜;死掉的直接从存档里消失,所以只能在结算那一刻交代。要不要让核心层把种类一起给出来,做牧场界面时定。 |
| 原型里做不做牧场的界面 | 牧场的规则和代码已经有了。不做的话,原型里的复习都在矿洞做,学习上不缺东西,但"农场加牧场是一条完整的路"在原型里验证不了。由负责人定。 |
| 牧场要不要等级才开放 | 现在一开始就有。草地本来就该一直开着(复习不设限);牲畜要钱,自然是后面的事。 |
| "换一个"怎么说才不被滥用 | 种田时换掉的新词隔天要考一次。按钮上要让玩家明白这一点;确认之前也不能先把释义摆出来。 |
| 玩家会不会把自己练烦了 | 矿洞不再因为田满而关门,词袋装满后可以一直练。题量没有上限:模拟里每次答 100 题的学习者每天约 260 题。练习是自愿的,但要看真人会不会停不下来又觉得累。见[数值与平衡](04-economy-balance.md#2-田满之后还能做什么)。 |
| 蒙对的词要不要再收紧 | 只有第一次作答算数,已经实现。第一次就蒙对的新词要等 3 天后复习才会被筛出来,模拟里 60 天后剩下的不到 3%。要不要加"不认识"按钮或缩短第一次休息,等真人数据再定。见[学习设计](03-learning.md#已知的弱点)。 |
| 学得快的人的复习高峰 | 挖新词没有每日上限,旧词会越积越多。 |
| 小镇里有什么 | 等级解锁的内容目前是占位表。 |
| 金币和矿石还能花在哪 | 金币严重过剩,矿石只能卖。矿石改成按概率出之后钱来得慢了一半左右,但仍然没有花钱的地方。要等家、装饰、工具这些出口设计出来。出最高级矿石的概率(现在封顶 30%,`TOP_ORE_CHANCE`)是金币来得多快的旋钮。 |
| 枯萎要不要有实际后果 | 现在只是警告。 |
| 学得吃力的玩家怎么托住 | 他们星级低、死亡多、收入少,有被劝退的风险。 |
| 怎么引导玩家尝试更难的题型 | 现在只靠售价倍率,效果未知。 |
| 每天只来一次的玩家 | 进度减半。 |
| 词库的释义怎么保证质量 | ECDICT 的释义偏长,需要改写。 |
| 上架算游戏还是学习工具 | 影响资质和变现方式,规则未核实。 |
| 名称的正式检索 | 英文名已改为 Lingdale(见[决策记录 0014](../decisions/0014-english-name-lingdale.md)),公开渠道没发现冲突。商标局的正式检索和各平台账号名还没查。对外发布内容之前必须完成。 |
| 第一篇内容要改 | [原稿 001](../marketing/drafts/001-why-a-farming-game.md) 和 SM-Intelligence 里已生成的各平台版本写的是加入矿洞之前的规则,发布前要按新规则改。 |
| 彩纸拼贴会不会显得像应用而不像游戏 | 这是选定的美术方向的主要风险。要等农场切片上真机、以及目标用户看到画面之后才能判断。 |
| 词袋多装几个、连对几次、几个词轮着练 | 现在是 10 个、5 次、5 个(`BAG_EXTRA`、`DRILL_STREAK`、`DRILL_SET`),都是开发时定的,没有真人数据。见[决策记录 0019](../decisions/0019-mine-stays-open.md)。 |
| 浇 5 次水是不是多了 | 按模型,第 1 次浇水正确率 82% 到 90%,第 2 次起都在 92% 以上,后几次考的大多是已经记住的东西,减到 3 次可能就够。但这只在模型的乐观值下成立:"看过一次就能记半天"是模型最没把握的地方,负责人也认为偏乐观,而且浇水次数还关系到收获的节奏。见[数值与平衡](04-economy-balance.md#2-浇-5-次水可能偏多)。 |
| 死亡和枯萎是不是摆设 | 按模型自己的初始值,作物死亡只发生在 0.3% 到 1% 的作物上;把"看一眼答案半天后还记得"调到 50% 是 2% 到 7%,调到 30% 是 7% 到 13%。要等真人数据。见[数值与平衡](04-economy-balance.md#3-作物几乎不会死)。 |
| 地块对爱挖矿的玩家没什么用 | 按模型,扩建到 120 块地,两条路线教会的词都只多一两成(两样都做 14%,种田放牧 18%)。地块作为金币的消耗和成长的目标,对后一类玩家几乎不成立。见[数值与平衡](04-economy-balance.md#4-限制速度的是什么)。 |
| 用真人数据校准记忆模型 | 模拟用的是公开模型的默认参数,不是我们玩家的。原型能玩之后,用作答日志核对:第一次浇水、各级复习、练出词袋后隔天再考的正确率,和模型给的差多少。最要紧的是"只看过一次答案,半天后还记得多少"。 |
| 开一块地能立刻恢复新词的额度 | 关门的画面上放了"再开一块地"。模拟里金币严重过剩,这个按钮会让"田有多大就学多少"变成"有钱就能多学"。放不放、放第几位、要不要涨价,由负责人定。 |
| 矿洞的画面要按新规则改 | 现有的示意稿是按"额度 = 空地 − 词袋,用完关门"画的。现在额度多了 10 个;矿洞不会因为田满而关门,"关门"的画面基本用不上了;新增了练习这种矿脉。见[美术规范](07-art-direction.md#还没定的)。 |
| 没有人提醒新玩家"该去种了" | 挖新词没有上限,开局还能答错 40 次(30 块空地加词袋多装的 10 个),新玩家可以一直挖下去,词袋越攒越多。见[开局的几步](07-art-direction.md#开局的几步)。新手引导还没有设计。 |
| 小镇里的家和以后的地点 | 地图上已经画了"家"和"以后开放"的空地。里面有什么、按等级还是词汇量开放,没有设计。见[决策记录 0018](../decisions/0018-town-map-as-hub.md)。 |
| 岩层构图像不像游戏 | 矿洞静止时最像一张选择题列表,游戏感要靠动效。要等能点的原型才能判断。见[决策记录 0017](../decisions/0017-mine-screens-art.md)。 |
