# 家的画面

第一级的房子、家里的一页、四个入口和玩家的角色。**现在只有给负责人挑选的方案,还没有定稿。**
挑定之后在这里画定稿,并把画法写进[美术规范](../07-art-direction.md)。

背景:小镇地图上一直画着"家"([决策记录 0018](../../decisions/0018-town-map-as-hub.md)),里面是什么没有设计。
2026-11-21 负责人给了方向:家可以升级,家里有四个玩法(升级和装饰、厨房、手工坊、衣帽间),见[决策记录 0026](../../decisions/0026-home-upgrades-and-four-activities.md);
玩家有一个自己的角色,在游戏里做的每件事都以它的名义,见[决策记录 0027](../../decisions/0027-player-character.md)。

这次只画最基础的房子和家,四个玩法只留入口。**四个玩法的规则、数值和里面的界面都没有设计;升级之后的房子和房间没有画;各种衣服没有画。**

| 一 家里怎么看 | A 剖面;B 俯视;C 正对一面墙 | A。外形和里面是同一张图,升级时一起变;所有东西只画正面,一个人做得过来;往上加层正好用上竖屏。代价是第一级只有一排地板,很挤 |
| 二 四个入口 | 甲 四样都是房间里的东西;乙 四个按钮;丙 三样东西加底部一个主要动作 | 丙。厨房、手工坊、衣帽间是灶台、工作台、衣柜;升级和装饰是对整个家做的事,放在底部右边 |
| 没开放怎么表示 | 纸模型;盖着一块布;上了色只靠名牌 | 纸模型。规范里已有的规则,和地图一致;截图发出去不会被当成已有的功能 |
| 三 房子的外形 | 1 山墙朝前;2 屋檐朝前;3 又窄又高带阁楼 | 1。就是地图上那个纸模型上了色;它的剖面就是 A 的房间 |

| 五 角色在别处怎么出现 | X 只有头像;Y 每个画面一个固定的位置,站着不走;Z 走到被点的东西旁边 | Y。看得到它和它的衣服,动作是它做的,又不挡东西、不拖慢答题。代价是矿洞和农场要重新排才放得下它 |

## 已经照规则排好的

不是方案,是照美术规范现有的规则排的;有不同意见再改。

- **进:** 在小镇地图上点房子或它的名牌。**回:** 左下角的"小镇",和农场、矿洞、商店的位置相同。
- **家里没有路牌。** 规范规定路牌只连农场和矿洞。从家去农场要经过地图。
- **词袋的按钮留着,**和商店的做法一样:在不学习的地方也看得到有几个词等着种。
- **顶部三个药丸不变。**

## 房子外形给地图用的尺寸

小镇地图的精修稿归另一张卡片(`docs/design/town-map/`,动手时那个目录还不存在)。房子的外形归这里,给地图用时照下面的来:

- **原点在墙脚正中,**地面那条线上。现有地图([`../mine-screens/screens.js`](../mine-screens/screens.js) 的 `townHome`)里,
  墙脚在 (292, 300) 附近,名牌的上沿在 y=308。新画的三种外形都能直接放在这个位置。
- **方案 1(建议的):** 墙 84×60,屋顶的尖离地 102,烟囱的烟到约 120;连左边的树一共宽约 130。和现有的纸模型是同一个轮廓。
  方案 2 墙 100×46、屋顶宽 116、高 80;方案 3 墙 64×72、屋顶的尖离地 126。
- **颜色:** 纸白的墙、屋顶红的屋顶、湿土色的门、墨绿的窗(窗不用蓝色)。没有新增颜色。
- **还没开放时是纸模型:** 同一组纸片,只用纸白和纸白暗,不画烟和窗台的花。`LD.home.kit.ext[1](true)` 就是它。
- **缩小:** 每栋约 40 像素宽时三种都认得出是房子,方案 1 最稳。见方案比较页"缩小了看"。
- **名牌第二行写什么没有定。** 别的地方写的是现在的状况,家还没有状况可写。

## 这些画面是怎么来的

- **全部用代码绘制。** JavaScript 运行时生成 SVG。没有使用图像生成模型,没有使用任何第三方图片。
- 代码由 Claude 编写,属于 AI 协助产出的内容。对外发布这些画面时,按[内容策略](../../marketing/01-content-strategy.md#红线)的要求声明。
- **它们是示意稿,不是成品。** 用途是检验构图、配色,以及在手机竖屏上、在小尺寸下认不认得出。
- **四个玩法都没有做。** 画面里它们一律是"还没开放"的样子。对外发布时不能把它们当成已有的;
  方案比较页里有一张"开放以后换上颜色"的小图,只用来说明开放时不用重画,不能单独拿出去用。
- **画面不读取游戏数据。** 顶部的数字和农场、矿洞的参考图是同一个示意存档(第 1 年夏季第 3 天)。
- **没有动效。**
- 不模仿任何具体的已有游戏的画面、角色、图标和配色。角色的三种草样是从这套画面自己的形状(圆、圆角方片、对折的纸)出发画的,
  没有参照任何具体角色;但"不像任何已有的人物"绘制者自己保证不了,对外发布前要负责人过目。
- **已有的矿洞、农场、小镇地图一笔没有改。** 方案比较页里角色出现在这些画面上、房子出现在地图上,
  都是在 `../mine-screens/screens.js` 画出来的画面上再叠一层。

## 检查过的

- `options.html` 在 1280 像素宽和 390 像素宽的视口下没有脚本报错;390 像素宽时没有横向溢出。
- 每张画面都按手机竖屏(390×844)截图看过。
- 三种房子外形缩到每栋约 40 像素宽、去掉颜色之后看过;三种角色缩到约 32pt 高、去掉颜色之后看过。

## 没检查的

- 没有上过真机,只在桌面浏览器里按手机宽度看过。
- 没有做色觉模拟,也没有算新出现的几对颜色的明暗对比(纸模型在蓝绿的墙上、角色的肤色在草地和矿壁上)。定稿时补。
- 没有问过任何目标用户。

## 画的时候发现的问题

都不是这次能定的,已经记进[路线图的未决问题](../06-roadmap.md#未决问题)。

- **四个入口都没开放的时候,家是一间只能看的空房间。** 家什么时候在地图上开放、开放时至少有哪件事能做,要定。
- **这四个玩法怎么和学习挂钩,没有回答。** 设计支柱第 6 条写的是"以后的每一种玩法,都是学习的地方",而做饭、手工、换装本身不是答题。
- **"送人"送给谁:** 居民没有设计。**鱼和收集品从哪来:** 钓鱼和收集没有设计。画面里只画了游戏里已经有的东西。
- **"蓝色只表示水"管不管衣服和家具。** 照现在的规则,角色不能穿蓝色的衣服。
- **现有的矿洞和农场没有给角色留位置,**两屏都排满了。
- **肤色和发色用了色板里现成的干土和墨绿。** 能不能选肤色、发型,角色有没有名字和表情,没有定。
- **牛奶、鸡蛋、羊毛都是白的,**和纸模型一个颜色,小尺寸下分不清。
- **搁板上摆着牛奶和鸡蛋,等于暗示库存在家里。** 仓库要不要搬进家,没有定。
- **点了还没开放的入口会怎样,**没有画。
