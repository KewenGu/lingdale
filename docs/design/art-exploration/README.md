## 怎么看

用浏览器打开 [`index.html`](index.html)。需要联网加载字体(Google Fonts);像素字体已经内嵌在 `fonts.css` 里。

页面从上到下是:四个方向并排的一屏农场、缩小到 120 块地时的样子、同一状态的逐项对比、每个方向的说明和生成提示词、
对照七条要求的评估、推荐。

## 四个方向

| | 方向 | 一句话 |
|---|---|---|
| A | 像素菜园 | 低分辨率、限定色板的像素画,像一块小小的电子菜园 |
| B | 水彩绘本 | 像手绘绘本里的一页:铅笔线稿、透明的淡彩、纸的肌理 |
| C | 彩纸拼贴 | 用彩色纸片剪出来、一层层贴起来的农场:纯色块、圆润的几何形状、没有描边 |
| D | 低多边形沙盘 | 一个低多边形 3D 的玩具农场沙盘,像桌面上的积木模型 |

每个方向的画风、配色、字体、状态表达、优点、风险和产能评估都在页面里,文字的出处是 [`directions.js`](directions.js)。

## 这些画面是怎么来的

- **全部用代码绘制。** 每个画风是一个 JavaScript 文件,运行时生成 SVG。没有使用图像生成模型,没有使用任何第三方图片。
- 代码由 Claude 编写,属于 AI 协助产出的内容。对外发布这些画面时,按[内容策略](../../marketing/01-content-strategy.md#红线)的要求声明。
- **它们是示意稿,不是成品。** 用途是检验配色、布局,以及各种状态在手机上、在小尺寸下认不认得出。
- **用代码画对四个方向不公平。** 代码最擅长的是纯色几何形状,所以 C 最接近它真实的样子;
  B 的水彩和 D 的 3D 用真正的工具做会好看得多,A 由熟练的像素画师来画也会更精致。
  比较"认不认得出"相对公平,比较"好不好看"时要考虑这一点。

## 场景和状态

所有画风画的是 [`scene.js`](scene.js) 里的同一份示意数据:第 1 年夏季第 3 天,30 块地,12 块能浇水,
2 株枯萎,3 株不生长,4 株浇对就收获,4 块空地。作物表、生长形态和健康状态的定义以[玩法规则](../02-gameplay.md)为准,
这里的数据是手写的示意,不从 `core/` 读取。

所有画风对状态的语义约定相同:

| 状态 | 约定 |
|---|---|
| 能浇水 | 干土(浅色)加地块右上角的水滴标记 |
| 今天浇过了,或今天刚种下 | 湿土(深色),没有标记 |
| 不生长 | 一片叶子发黄,姿态稍歪,不加警告图标 |
| 枯萎 | 整株下垂,叶色偏黄褐。不吓人 |
| 品质 | 地块下沿 5 个小点或小星,亮的是剩下的星数 |
| 浇对就收获 | 地块左上角一个金色小标记 |
| 空地 | 一块翻好的土 |

## 导出图文组

用浏览器打开 `cards.html`,每个 `.card` 元素是一张 1080×1440 的图,按 1 倍像素比逐个截图即可。
仓库里的 9 张是用 Playwright 这样导出的,再做了无损压缩。改了卡片内容或任何一个画风的绘制代码之后,要重新导出。

## 守的规矩

- 不模仿任何具体的已有游戏的画面、角色、图标和配色方案。
- 不出现修仙题材的视觉元素。"灵谷"这个名字带来的误会要靠画面拉回田园小镇,见[决策记录 0011](../../decisions/0011-name.md)。
- 枯萎和空地不吓人,不让人愧疚。
- 状态不只靠色相区分:能浇水有水滴,枯萎有姿态变化。
